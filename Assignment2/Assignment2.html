Noisy House

Musical Game for Toddler

Introduction

Noisy House is a browser-based music game designed for toddlers. The idea is to let toddlers explore everyday objects in a kitchen and bathroom and discover the sounds they can make. When the user hovers over a sticker, it plays a short sound sample, and when they click the sticker, the sound is added to the loop, so they can mix sounds and create different combinations without the need to understand music theory or follow specific rules. In design perspectives, I made the interface to be simple and playful with less reliance on text because the target audience is toddlers. I explored this through 6 prototypes. The first 3 prototypes focus on the sticker interaction, while other 3 explore different ways to switch between the kitchen and bathroom.

The extended technique I chose is mouse movement. It is tracking the mouse position. When users move the mouse from left to right, it changes the sound between the left and the right speaker. Similar to up and down, which controls the volume. The purpose of this is to give the user another way to experiment with sounds and make the interaction feel more playful.

1. Sticker prototypes

The first 3 prototypes focus on the sticker buttons because they are the main ways user use it to interact with sound and browser. Main goal of this experiment is to find a design that make it clear and obvious which objects can be click, and easy for toddlers to understand browser’s functions and the difference between listening to sample and adding sound to the loop.

Prototype 2 - Differenciate between 2 mode - sample playing and adding to loop

From the first prototype, I realized that I needed to make the stickers more noticeable and communicate the difference between the two sound interactions. When the user hovers over a sticker, it moves up slightly and becomes brighter to show that a sample is playing. When the user clicks the sticker, it moves down and becomes darker to show that the sound has been added to the loop. I wanted these two actions to have a clear visual contrast, so the user does not only hear the difference but can also see what is happening. This made the interaction easier to understand without reading written instructions.

Prototype 3 - Add border aroung sticker

After testing the previous version, I started thinking about my target user, which is toddlers. Then, I realized that making the interface look realistic or minimal is not always the most effective. It may be better to make it obvious where the user can interact. I added a thick border around the stickers, similar to the white border usually seen around real stickers. It makes the objects feel more like buttons instead of just images placed on the background. In my opinion, this prototype might be more suitable for a toddler compared to the previous one because it makes the interface feel more playful and clear.

2. Narvigation prototypes

These prototypes is experimenting about how the user can switch between kitchen and bathroom pages. The aim of this is to find a navigation style that could communicate the two environments without depending on text because toddlers do not have the ability to read yet.

Prototype 1 - Basic Button

Figure.7 - Browser layout of prototype 1

The first experiment is a standard button with text and an icon. The benefit of this design is that it is very easy to understand for person who can read. However, this design relies heavily on text, which may not work well for toddlers. Although the icons give some visual information, they are quite small, and the text is still the main way of communicating the function.

Prototype 2 - Icon button

Figure.10 - Browser layout of prototype 2

In this experiment, I replace the text buttons with larger images. I use a pan to represent the kitchen and a bathtub to represent the bathroom. I choose familiar objects because they are easier for a toddler to recognize than written words. I also make the buttons larger and add a border, so they look more like buttons or stickers instead of just images on the page. I think this design is a better way to communicate with toddlers and more suitable for the visual style of the game, but I also realize that these two buttons do not show connection to the main game. It might lead to confusion for toddlers.

Prototype 3 - Switch Toggle

Figure12 - Browser layout of prototype 3

In this prototype, I use a switch toggle to move between the kitchen and bathroom. The left side represents the kitchen, and the right side represents the bathroom, with the icon inside the circle changing depending on the selected environment. I chose this because the movement of the toggle can show that there are two different choices without needing text. I also give each environment a color theme, orange for kitchen and blue for bathroom, and both using the same tone. This makes the two environments feel different while still being part of the same game.
